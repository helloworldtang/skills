# 平台规格与文案字段

## 一条总原则

网上流传的"官方上限"互相矛盾（同一个视频号，文件上限有写 1GB 的、也有写 20GB 的；小红书时长有写 1 分钟的、也有写 15 分钟的）。原因：**上限会按账号权重、客户端版本、灰度实验变化**。

所以策略是：**打安全区，不打上限**。下面的"安全区"是实测能过的值，不是理论最大值。真要探边界，用后台的报错当准绳，别信攻略文章。

---

## 安全区（三个平台都能过的一套参数）

| 项 | 取值 | 说明 |
|---|---|---|
| 容器 | MP4 | `-movflags +faststart` |
| 视频 | H.264 High，level 自动（见下） | 平台普遍只认 H.264；H.265 兼容性差 |
| 像素格式 | yuv420p | 非 420 会被拒或变灰 |
| 帧率 | 30fps CFR | VFR 会导致音画不同步 |
| 分辨率 | 1080 短边起 | 见下方每平台 |
| 音频 | AAC 48kHz 立体声 128–192kbps | 必须有音轨 |
| 响度 | **−16 LUFS / −1.5 dBTP** | 信息流平台通用目标 |
| 时长 | ≤ 5 分钟最稳 | 知识类内容 2–5 分钟合适 |
| 体积 | ≤ 500MB | 远小于各家上限，上传快、转码快 |

**H.264 level 别手写**，按宏块算：`ceil(w/16) × ceil(h/16)` 和 `× fps` 都要在上限内。
`build.py` 自动算。参考结果：1920x1080→4.1、1080x1440→4.0、1080x1920→4.1、1920x1246→5.0。

## 每平台的取舍

### 视频号

| | |
|---|---|
| 主推画幅 | **9:16（1080x1920）** 或 **3:4（1080x1440）** |
| 横屏 | 支持 16:9，但信息流里占屏小、上下加黑边 |
| 我的做法 | 内容区是 1360x1722 这种比例时，出 **3:4**——原生比例，无补边 |
| 封面 | 与视频同比例，别用横图 |
| 注意 | 分享到朋友圈会被裁成方形，**核心信息放中央** |

### 小红书

| | |
|---|---|
| 主推画幅 | **9:16（1080x1920）**；但瀑布流 **双列卡片按 3:4 居中裁切预览** |
| 关键设计 | 做 9:16 时让内容落在垂直居中的 ~71% 区域内（1080x1920 里约 1368px 高）→ 卡片预览不裁内容，点开又是全屏 |
| 封面 | 从视频截 3:4 帧，比另做封面更统一 |
| 标题 | ≤ 20 字，前 10 字最关键（会被截断） |
| 正文 | 一句话结论 + 三条依据 + 话题标签，控制在 300 字内 |

### B 站

| | |
|---|---|
| 主推画幅 | **16:9（1920x1080）**，这是主战场 |
| 竖屏 | 支持 1080x1920，但播放器两侧大黑边，除非本来就该竖着看 |
| 分区 | 技术类选「科技 → 计算机技术」 |
| 标题 | 可用 40 字左右，但信息流只显示前 ~25 字 |
| 简介 | 300 字内；**放不进画面的信息（地址栏、仓库名、命令）写这里** |
| 上传 | 选「1080P 高清」，关掉"智能压缩"一类选项 |

## 文案字段模板

### 标题的三个版本

同一个内容，三个平台的语气不一样：

| 平台 | 语气 | 例子 |
|---|---|---|
| 视频号 | 平实、对公众号读者 | 「语音对话延迟压到 280ms：ASR+TTS 全链路本机实测」 |
| 小红书 | 有冲突感、第一人称 | 「语音对话 280ms，评论区都说不可能」 |
| B站 | 可直接带技术细节 | 「被评论区说「300ms 不可能」，我把本机全链路录下来了（无剪辑）」 |

### 描述/简介的骨架

```
一句话结论（带数字）
—— 这条片子是什么：真机录屏 / 无剪辑 / 哪套配置
—— 差在哪：2–3 条具体机制
—— 怎么看：告诉观众去哪里核对（画面里的哪个位置、哪条命令）
#话题1 #话题2 #话题3
```

**关键**：如果画面里放不下某个证据（被裁掉了），必须在这一段补上。这是裁切决策的配套动作，不是可选项。

### 封面

- 从视频里截一帧，**优先选"信息密度最高"的那一帧**（有数字、有表格的那种），不要选封面式的大字图
- 加文字的话，手机上能看清的字号下限约等于画面高度的 1/12
- 时长超过 1 分钟的视频，封面决定点击率，值得单独花时间

## 上传后

- 平台转码 + 审核，几分钟到几小时
- **转码后再看一遍**：平台的二次压缩可能把细字压糊。这是唯一能验证"文字在手机上能不能看清"的时机
- 如果糊了，正确做法是**提高源片码率/降低 CRF 重传**，不是加锐化
