# 成文协作三关

原则：**方向在 300 字内确认，不在 3000 字后返工**。每一关有明确的退出条件，不满足不进下一关。

文章长度只服从讲清中心问题的最低需要——100 字讲得清就 100 字，字数不是目标。公众号正文上限 2 万字符（平台天花板，见微信草稿箱接口文档），逼近上限通常是中心不单一，回第一关检查。

## 第一关：挖料（不动笔）

1. 五问：给哪个号 / 读者是谁 / 读完希望他干什么 / 已有什么素材 / 有什么禁忌
2. 让用户 info dump（排错记录/聊天记录/数据，不用整理），有 MCP 或文件就直读
3. Claude 反问 5-10 个补洞问题，用户可简答（"1:是 2:见xx记录"）
4. **退出条件**：Claude 能主动问到边缘 case 和取舍点 = 上下文够了
   转场话术：「还有要补的吗？没有就开始搭骨架」

## 第二关：逐节选材后写

1. 定节标题骨架（3-5 节），引用文体 skill 定结构：踩坑复盘 → problem-driven-article 九段；其他文体现场定骨架请用户确认
2. 从「未知数最多」的节写起，摘要/收尾最后写
3. 每节固定节奏：列 5-20 个内容点 → 用户圈选（留/删/合并）→ 补漏问一句 → 才动笔 → 用户口头提修改意见，Claude 手术式小改，不重印全文
4. 用户反馈是学偏好：本节的修改模式应用到后续节的初稿里
5. 节完成判据：连续 3 轮无实质修改 + 问一句「有没有能删的」

## 第三关：盲测验收

1. Claude 起零上下文 sub-agent，只给成稿全文
2. 预测 5-10 个读者真会问的问题，逐个让 sub-agent 只凭成稿回答
3. sub-agent 答错/答不出/含糊的点 = 读者也会卡 → 标出回炉该节
4. 附加三问：哪里有歧义？默认了读者什么前置知识？有无前后矛盾？
5. **退出条件**：sub-agent 连续全对且无新盲区 → 提醒用户终读一遍（文章主人是用户），过 article-deslop 门禁后再走 wxpub 投递

## 红线

- 任何一关用户说「直接写/跳过」，立即降级为自由写作，不推销流程
- 标题候选全量呈现，拍板权留用户
- 本 skill 不含任何文体模板，动笔时必须引用结构 skill
